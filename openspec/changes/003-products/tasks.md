> Source of truth for behavior: `docs/specs/003-products.md` (read-only; status "Lista para Design"; §4, PRD-001..PRD-020 without PRD-006, E-01..E-72 without E-12, E-13, E-18, DEC-PRD-01..DEC-PRD-53 all `Confirmada`; DT-01, DT-02, DT-03 confirmed in design).
> Plan: `openspec/changes/003-products/design.md` (the project's only plan artifact; 21 decisions, test map, 25-slice outline, five business gaps P-1..P-5 resolved by DEC-PRD-49..53).
> Naming: `Phase N` = design slice N. Phase 14 holds two units (14a products, 14b combos) that are two commit/PR candidates; every other phase is one work unit. Task numbers (`N.M`) are continuous within a phase.
> Test-first (Strict TDD, `openspec/config.yaml`): every behavior is RED (Pest test named with its scenario or decision ID, e.g. `it('E-48 ...')`) then GREEN then REFACTOR. Authorization tests call HTTP endpoints, never the UI. `sail` below means `./vendor/bin/sail` (the alias does not exist in non-interactive shells). Edit files with the editor tools only; run tests as a separate command.
> Test runner: `sail artisan test` (full) / `sail pest --filter=<ScenarioID>` (scoped).
> Slice-close gate (the last task of every phase; backend-only phases run the JS gates too because they are cheap and catch Wayfinder/type drift): `sail pint --test`, `sail composer types:check`, `sail pnpm check`, `sail pnpm types:check`, `sail pnpm build`, `sail artisan test`.
> Commits: one Conventional Commit per work unit citing the spec, e.g. `feat(003): ... [PRD-001]`. Per AGENTS.md §11 no commit, push or PR is made unless the user asks.
> Privacy: the real catalog files (Anexo A/B, fabric and color file, Los Cedros codes) are never committed or saved to Engram. All fixtures, factories and CSV files are fictitious; CSVs are generated at runtime in a temporary directory. No real prices in seeds, factories or tests.
> Deferred scenario: E-29 (deletion blocked by history) cannot be tested in 003; it is recorded as a Pest `->todo()` in Phase 16 and tested by 004, 006 and 008.
> Guard hooks: guards whose target tables arrive in a later slice ship as empty, documented hooks and are filled by the slice named in the task (design Decisions 9, 10, 11, 17). Each hook task names its filling task so none is forgotten.
> Redirect precedent: write slices whose redirect target page arrives later (e.g. `products.show` in Phase 17) follow the 002 precedent (store/update tests assert the redirect `Location` path; the named route is declared when the page ships). See Risk R-3.
