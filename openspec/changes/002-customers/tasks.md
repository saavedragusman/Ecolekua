# Tasks: 002-customers — Customer Registry, Advisor Portfolio and One-Time Import

> Source of truth for behavior: `docs/specs/002-customers.md` (status `Confirmada`; CLI-001..CLI-018, E-01..E-41, DEC-CLI-01..DEC-CLI-33, DT-01 confirmed in design Decision 4).
> Plan: `openspec/changes/002-customers/design.md` (the project's only plan artifact; 16 decisions, test map, 9-slice outline, DEC-CLI-33 resolved as the `VenezuelanState` enum).
> Naming: `Phase N` = design slice N. Phases with more than one lettered work unit (`2a`, `2b`, ...) are split so each unit is a commit/PR candidate that can be green on its own. Task numbers (`N.M`) are continuous within a phase.
> Test-first (Strict TDD, `openspec/config.yaml`): every behavior is RED (test named with the scenario ID, e.g. `it('E-14 ...')`) then GREEN then REFACTOR. Authorization tests call HTTP endpoints, never the UI. `sail` below means `./vendor/bin/sail` (the alias does not exist in non-interactive shells).
> Test runner: `sail artisan test` (full) / `sail pest --filter=<ScenarioID>` (scoped).
> Slice-close gate (repeated as the last task of every phase): `sail pint --test`, `sail composer types:check`, `sail pnpm types:check`, `sail pnpm build`, `sail artisan test`. Phases without frontend changes still run all five (they are cheap and catch Wayfinder/type drift).
> Commits: one Conventional Commit per work unit citing the spec, e.g. `feat(002): ... [CLI-001]`. Per AGENTS.md §11, no commit, push or PR is made unless the user asks.
> Privacy: the real import file is never committed or saved to Engram. All fixtures and CSV files are fictitious and generated at runtime in a temporary directory. No real prices, customers or employees in seeds, factories or tests.
> Scenarios without an E-ID in the source: CLI-007 and CLI-013 get plain behavior tests named by requirement (`it('CLI-007 ...')`, `it('CLI-013 ...')`); no new E-IDs are invented.
